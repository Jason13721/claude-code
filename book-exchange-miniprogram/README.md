# 邻里换书 · 小区童书交换小程序（可点击原型）

让孩子读完闲置的书在小区内流动起来。用「书币」解耦“给”与“取”，
让每一次贡献都能换来想读的书 —— 不是单向捐赠，而是互惠互助。

> 这是一个**可点击原型**：所有数据都在内存里（`utils/store.js`），
> 重启小程序即重置为初始演示数据。尚未接后端 / 云开发。

## 核心机制：书币（积分制）

为什么不用“一对一交换”？因为它要求“我有你想要的书、同时你有我想要的书”，
这种**双重需求巧合**概率极低，会让书很难流动。书币把两端拆开：

- **贡献一本书（上架）→ 获得书币**（按品相、品类浮动定价）
- **想要别人的书 → 用书币兑换**
- 线下楼下当面交接，省去快递，邻里更安心

定价规则见 `utils/store.js` 的 `creditFor()`：基础 8 分 + 品相加成 + 品类加成，最低 5。

## 范围：先从单个小区试点

书架只展示**同一小区**内的书。单小区起步的好处：信任成本低、物流几乎为零、
同小区年龄结构相近使童书供需天然对齐。跑通后再“按小区复制”。

## 完整可点击闭环

1. **书架**（首页）：浏览本小区的书，按分类筛选，顶部显示书币余额
2. **书籍详情**：查看简介与提供者，点「兑换」扣书币、生成待交接订单
3. **发布**：填写书名/分类/品相等，实时预估可得书币，上架即到账
4. **兑换记录**：兑入 / 上架记录，待交接订单可「确认交接」
5. **我的**：书币钱包、我发布的书、书币明细

## 如何运行

### 方式一：浏览器直接跑（最快，零安装）

`web-demo/` 是一个浏览器版，**复用了小程序的真实业务逻辑**（`utils/store.js`），
界面也是同款，用来快速点着体验整个闭环：

```bash
cd book-exchange-miniprogram
python3 -m http.server 8099
# 浏览器打开 http://127.0.0.1:8099/web-demo/index.html
```

> `web-demo/screenshots/` 里是用无头浏览器自动跑通后截下的运行效果图。

### 方式二：微信开发者工具（真机/小程序环境）

1. 用[微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)打开本目录
2. AppID 选择「测试号」（项目已设为 `touristappid`）
3. 编译即可在模拟器中点击体验

## 目录结构

```
book-exchange-miniprogram/
├── app.js / app.json / app.wxss   # 全局入口、配置、样式
├── project.config.json            # 开发者工具项目配置
├── sitemap.json
├── utils/store.js                 # 书币规则 + 演示数据（原型的“大脑”）
└── pages/
    ├── index/     书架（首页 tab）
    ├── detail/    书籍详情 + 兑换
    ├── publish/   发布闲置书（tab）
    ├── orders/    兑换记录
    └── mine/      我的（tab）
```
